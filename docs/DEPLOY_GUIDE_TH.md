# คู่มือ Deploy NEXUS ERP (ฉบับทำตามได้ทีละขั้น)

คู่มือนี้พาเอาโค้ดชุดแก้ไขความปลอดภัยและบัญชีขึ้นระบบจริง ไม่ต้องมีพื้นฐานเขียนโปรแกรม
ทำตามลำดับ **ห้ามสลับขั้น** เพราะต้อง deploy แอปก่อน แล้วค่อย deploy rules

| ขั้น | ทำอะไร | ใช้เวลาประมาณ |
|---|---|---|
| 1 | ตั้งรหัส `CRON_SECRET` ใน Vercel | 5 นาที |
| 2 | ส่งโค้ดขึ้น GitHub (Vercel จะ deploy แอปเอง) | 10 นาที |
| 3 | ทดสอบแอปบนเว็บจริง | 10 นาที |
| 4 | Deploy Firestore Rules (กฎความปลอดภัยของฐานข้อมูล) | 5 นาที |
| 5 | ทดสอบอีกรอบหลัง deploy rules | 10 นาที |

> **ทำไมต้องเรียงแบบนี้:** แอปเวอร์ชันใหม่ทำงานได้กับทั้ง rules เก่าและ rules ใหม่
> แต่แอปเวอร์ชันเก่าบางหน้า (เช่น หน้าใบเสนอราคา) จะใช้ไม่ได้กับ rules ใหม่

---

## ขั้นที่ 1: ตั้งรหัส CRON_SECRET ใน Vercel

`CRON_SECRET` คือรหัสลับที่ Vercel ใช้ยืนยันตัวตนเวลาเรียกงานอัตโนมัติรายวัน (ตรวจอุปกรณ์ใกล้หมดประกัน)
ถ้าไม่ตั้ง งานอัตโนมัตินี้จะถูกปฏิเสธ

**1.1 สร้างรหัสสุ่ม**
1. กดปุ่ม Windows พิมพ์ `PowerShell` แล้วกด Enter
2. คัดลอกคำสั่งนี้ไปวาง แล้วกด Enter
   ```powershell
   [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
   ```
3. จะได้ตัวอักษรยาว 64 ตัว ให้คัดลอกเก็บไว้ (**ห้ามส่งให้ใคร**)

**1.2 ใส่รหัสใน Vercel**
1. เข้า <https://vercel.com> แล้วล็อกอิน
2. คลิกโปรเจกต์ NEXUS ERP
3. ไปที่แท็บ **Settings** แล้วเลือกเมนูซ้าย **Environment Variables**
4. ช่อง **Key** ใส่ `CRON_SECRET` ส่วนช่อง **Value** วางรหัสจากข้อ 1.1
5. ช่อง Environment ติ๊ก **Production** (จะติ๊ก Preview ด้วยก็ได้)
6. กด **Save**

**1.3 เช็กว่าตัวแปรเดิมครบ**
ในหน้าเดียวกัน ต้องมีตัวแปรเหล่านี้อยู่แล้ว ถ้าไม่มีให้หยุดแล้วแจ้งผู้ดูแลระบบ:
`FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`, `NEXT_PUBLIC_FIREBASE_PROJECT_ID`, `NEXT_PUBLIC_FIREBASE_API_KEY`,
`NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`, `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`, `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`,
`NEXT_PUBLIC_FIREBASE_APP_ID`, `GEMINI_API_KEY`

## ขั้นที่ 2: ส่งโค้ดขึ้น GitHub

Vercel ผูกกับ GitHub ไว้แล้ว เมื่อโค้ดเข้า branch `main` บน GitHub แล้ว Vercel จะสร้างเว็บเวอร์ชันใหม่ให้เอง

1. เปิดโปรเจกต์ใน VS Code
2. เปิด Terminal โดยกด `` Ctrl + ` `` (ปุ่มตัวหนอนใต้ปุ่ม Esc)
3. พิมพ์คำสั่งทีละบรรทัด กด Enter หลังแต่ละบรรทัด และรอให้บรรทัดก่อนหน้าทำงานเสร็จก่อน
   ```bash
   git switch main
   git merge fix/accounting-numbering-security
   git push origin main
   ```
   - ถ้าบรรทัดแรกขึ้นว่า *"Your local changes would be overwritten"* ให้หยุด แล้วแจ้งผู้ดูแลระบบ
   - ถ้า `git push` ขอให้ล็อกอิน GitHub ให้ล็อกอินด้วยบัญชีที่มีสิทธิ์ในโปรเจกต์
4. กลับไปที่ Vercel แล้วเปิดแท็บ **Deployments**
   - จะเห็นรายการใหม่ขึ้นสถานะ **Building**
   - รอประมาณ 2–5 นาทีจนเปลี่ยนเป็น **Ready** (จุดสีเขียว)
   - ถ้าขึ้น **Error** (สีแดง) ให้คลิกเข้าไปดู แล้วคัดลอกข้อความ error ส่งให้ผู้ดูแลระบบ เว็บเดิมยังใช้งานได้ตามปกติ

## ขั้นที่ 3: ทดสอบแอปบนเว็บจริง

เปิดเว็บไซต์จริงแล้วล็อกอินด้วย `admin@admin.com` จากนั้นลองทีละข้อ และติ๊กเมื่อผ่าน:

- [ ] หน้า Dashboard เปิดได้ ไม่มีหน้าขาว
- [ ] **ใบเสนอราคา:** สร้างใหม่ได้ เลขเอกสารขึ้นถูกต้อง ไม่มีคำว่า `TEMP`
- [ ] **ใบเสนอราคา:** หัวกระดาษขึ้นชื่อบริษัท
- [ ] **POS:** ขายสินค้า 1 ชิ้นได้ ขึ้นข้อความชำระเงินสำเร็จ
- [ ] **รับสินค้า (Goods Receipt):** บันทึกได้ และจำนวนสต็อกเพิ่มขึ้น
- [ ] **การเงิน:** เปิดหน้ายื่นภาษี ภ.พ.30 แล้วตัวเลขขึ้น

ถ้ามีข้อไหนไม่ผ่าน ให้จดว่าหน้าไหนและขึ้นข้อความอะไร **ยังไม่ต้องไปขั้นที่ 4**

## ขั้นที่ 4: Deploy Firestore Rules

Firestore Rules คือกฎที่กำหนดว่าใครอ่านหรือแก้ข้อมูลไหนได้
ตอนนี้กฎที่ใช้อยู่อนุญาตให้ทุกคนที่ล็อกอินเห็นข้อมูลของ **ทุกบริษัท** กฎใหม่จะแยกข้อมูลแต่ละบริษัทออกจากกัน

**4.1 สำรองกฎเดิมไว้ก่อน (สำคัญ)**
1. เข้า <https://console.firebase.google.com> แล้วเลือกโปรเจกต์ **nexuserp-base**
2. เมนูซ้ายเลือก **Firestore Database** แล้วกดแท็บ **Rules**
3. คลิกในกล่องข้อความ กด `Ctrl + A` แล้ว `Ctrl + C`
4. เปิด Notepad วางข้อความ แล้วบันทึกเป็นไฟล์ `rules-backup.txt`

**4.2 Deploy กฎใหม่**
1. กลับไปที่ Terminal ใน VS Code
2. พิมพ์คำสั่งนี้แล้วกด Enter
   ```bash
   npx firebase deploy --only firestore:rules
   ```
3. รอจนขึ้นข้อความ **`Deploy complete!`** (ประมาณ 30 วินาที)
   - ถ้าขึ้นว่าต้องล็อกอิน ให้พิมพ์ `npx firebase login` แล้วล็อกอินด้วย `psgsolution@gmail.com` จากนั้นทำข้อ 2 ใหม่

## ขั้นที่ 5: ทดสอบหลัง deploy rules

1. ปิดเบราว์เซอร์ทั้งหมด แล้วเปิดเว็บใหม่
2. ล็อกอิน `admin@admin.com` แล้วทำ checklist ในขั้นที่ 3 ซ้ำอีกรอบ
3. ล็อกอิน `sadmin@admin.com` แล้วเช็กว่าเปิดหน้า Dashboard และหน้าตั้งค่าได้

ถ้าผ่านทั้งหมดถือว่าเสร็จ 🎉

---

## ถ้ามีปัญหา: วิธีย้อนกลับ

**ย้อน Rules (ใช้เวลา 1 นาที)**
1. Firebase Console → **Firestore Database** → แท็บ **Rules**
2. ลบข้อความในกล่องทั้งหมด แล้ววางข้อความจากไฟล์ `rules-backup.txt` ที่สำรองไว้ในขั้น 4.1
3. กด **Publish**

**ย้อนแอป (ใช้เวลา 1 นาที)**
1. Vercel → โปรเจกต์ → แท็บ **Deployments**
2. หา deployment ก่อนหน้าที่สถานะ **Ready**
3. กดปุ่ม **⋯** ด้านขวา แล้วเลือก **Promote to Production** (หรือ **Instant Rollback**)

> ถ้าต้องย้อนทั้งสองอย่าง ให้ **ย้อน Rules ก่อน** แล้วค่อยย้อนแอป

## เพิ่มผู้ใช้ใหม่ (หลังใช้กฎใหม่แล้ว)

กฎใหม่ให้เข้าระบบได้เฉพาะผู้ใช้ที่มี "โปรไฟล์" ในฐานข้อมูล ตอนนี้หน้าสมัครสมาชิกยังเป็นตัวอย่าง (mock) จึงต้องเพิ่มผู้ใช้ด้วยมือ:

1. Firebase Console → **Authentication** → **Add user** ใส่อีเมลและรหัสผ่าน แล้วกด Add
2. คัดลอกค่า **User UID** ของผู้ใช้ที่เพิ่งสร้าง
3. ไปที่ **Firestore Database** → แท็บ **Data** → collection **users** → กด **Add document**
4. ช่อง **Document ID** วาง UID จากข้อ 2
5. เพิ่ม field (ชนิด **string** ทั้งหมด) ตามตาราง แล้วกด **Save**

| Field | ตัวอย่างค่า | ความหมาย |
|---|---|---|
| `companyId` | `COM-NEXUS-01` | รหัสบริษัทที่ผู้ใช้สังกัด |
| `role` | `ADMIN` หรือ `SALES` / `ACCOUNTANT` / `ENGINEER` / `HR` / `PURCHASING` | สิทธิ์การใช้งาน |
| `email` | `user@company.com` | อีเมล |

> ห้ามตั้ง `role` เป็น `SUPERADMIN` ให้ผู้ใช้ทั่วไป
