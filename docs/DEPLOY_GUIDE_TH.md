# คู่มือ Deploy NEXUS ERP (ฉบับทำตามได้ทีละขั้น)

คู่มือนี้พาเอาโค้ดชุดล่าสุดขึ้นระบบจริง ไม่ต้องมีพื้นฐานเขียนโปรแกรม
ทำตามลำดับ **ห้ามข้ามหรือสลับขั้น** ใช้เวลารวมประมาณ 1 ชั่วโมง

| ขั้น | ทำอะไร | ใช้เวลาประมาณ |
|---|---|---|
| 0 | เตรียมเครื่อง | 5 นาที |
| 1 | ตั้งรหัส `CRON_SECRET` ใน Vercel | 5 นาที |
| 2 | Deploy ดัชนีฐานข้อมูล (Indexes) | 10 นาที |
| 3 | ส่งโค้ดขึ้น GitHub แล้วให้ Vercel สร้างเว็บใหม่ | 10 นาที |
| 4 | ทดสอบเว็บจริง (รอบที่ 1) | 15 นาที |
| 5 | สำรองกฎเดิม แล้ว Deploy กฎความปลอดภัย (Rules) | 5 นาที |
| 6 | ทดสอบเว็บจริง (รอบที่ 2) | 15 นาที |

> **ทำไมต้องเรียงแบบนี้**
> - ดัชนีต้องสร้างเสร็จก่อน ไม่อย่างนั้นบางหน้าจะโหลดรายการไม่ขึ้น
> - เว็บเวอร์ชันใหม่ใช้ได้ทั้งกับกฎเก่าและกฎใหม่ แต่เว็บเวอร์ชันเก่าใช้กับกฎใหม่ไม่ได้
>   จึงต้องขึ้นเว็บใหม่ก่อน แล้วค่อยเปลี่ยนกฎ

**คำศัพท์ที่จะเจอ**
- **Terminal**: หน้าต่างสำหรับพิมพ์คำสั่ง อยู่ด้านล่างของ VS Code
- **Vercel**: บริการที่รันเว็บ NEXUS ERP ให้คนอื่นเข้าใช้
- **GitHub**: ที่เก็บโค้ด เมื่อโค้ดเข้า branch `main` แล้ว Vercel จะสร้างเว็บใหม่ให้เอง
- **Firebase**: ฐานข้อมูลของระบบ
- **Rules**: กฎว่าใครอ่านหรือแก้ข้อมูลไหนได้
- **Indexes**: ดัชนีที่ช่วยให้ค้นข้อมูลเร็ว

## ขั้นที่ 0: เตรียมเครื่อง

1. เปิดโปรแกรม **VS Code** แล้วเปิดโฟลเดอร์ `D:\NEXUS-ERP`
2. เปิด Terminal โดยกด `` Ctrl + ` `` (ปุ่มตัวหนอน อยู่ใต้ปุ่ม Esc)
3. ถ้าหน้าจอเว็บที่รันในเครื่อง (`npm run dev`) เปิดอยู่ ให้คลิกในหน้าต่าง Terminal นั้นแล้วกด `Ctrl + C` เพื่อหยุดก่อน
4. พิมพ์คำสั่งนี้แล้วกด Enter เพื่อดูว่าตอนนี้อยู่ที่ branch ไหนและมีไฟล์ค้างแก้ไหม
   ```bash
   git status
   ```
   - บรรทัดแรกควรเป็น `On branch feature/sales-real-data`
   - บรรทัดสุดท้ายควรเป็น `nothing to commit, working tree clean`
   - ถ้ามีรายชื่อไฟล์สีแดงหรือสีเขียวขึ้นมา ให้**หยุด**แล้วแจ้งผู้ดูแลระบบ

> **วิธีพิมพ์คำสั่งใน Terminal:** คัดลอกคำสั่งในกล่อง แล้วคลิกขวาใน Terminal เพื่อวาง
> จากนั้นกด Enter **รอจนคำสั่งทำงานเสร็จ** (มีบรรทัดว่างให้พิมพ์ต่อ) ก่อนพิมพ์คำสั่งถัดไป

## ขั้นที่ 1: ตั้งรหัส CRON_SECRET ใน Vercel

`CRON_SECRET` เป็นรหัสลับที่ Vercel ใช้ตอนเรียกงานอัตโนมัติรายวัน ซึ่งมี 2 งาน:
- ตรวจอุปกรณ์ที่ใกล้หมดประกัน
- ตรวจใบเสนอราคาที่ใกล้หมดอายุ

ถ้าไม่ตั้งรหัสนี้ งานอัตโนมัติจะถูกปฏิเสธ แต่เว็บส่วนอื่นยังใช้งานได้ตามปกติ

**1.1 เช็กก่อนว่าเคยตั้งไว้แล้วหรือยัง**
1. เข้า <https://vercel.com> แล้วล็อกอิน
2. คลิกโปรเจกต์ NEXUS ERP
3. ไปที่แท็บ **Settings** แล้วเลือกเมนูซ้าย **Environment Variables**
4. ถ้าในรายการมี `CRON_SECRET` อยู่แล้ว ให้**ข้ามไปขั้นที่ 2** ได้เลย

**1.2 สร้างรหัสสุ่ม**
1. กดปุ่ม Windows พิมพ์ `PowerShell` แล้วกด Enter
2. วางคำสั่งนี้แล้วกด Enter
   ```powershell
   [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")
   ```
3. จะได้ตัวอักษรยาว 64 ตัว ให้คัดลอกไว้ (**ห้ามส่งให้ใคร ห้ามแปะในแชท**)

**1.3 ใส่รหัสใน Vercel**
1. ในหน้า Environment Variables ช่อง **Key** ใส่ `CRON_SECRET`
2. ช่อง **Value** วางรหัสจากข้อ 1.2
3. ช่อง Environment ติ๊ก **Production**
4. กด **Save**

**1.4 เช็กว่าตัวแปรอื่นครบ**
ในหน้าเดียวกันต้องมีตัวแปรต่อไปนี้ ถ้าขาดตัวไหนให้หยุดแล้วแจ้งผู้ดูแลระบบ:
- `FIREBASE_CLIENT_EMAIL`
- `FIREBASE_PRIVATE_KEY`
- `NEXT_PUBLIC_FIREBASE_PROJECT_ID`
- `NEXT_PUBLIC_FIREBASE_API_KEY`
- `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`
- `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`
- `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`
- `NEXT_PUBLIC_FIREBASE_APP_ID`
- `GEMINI_API_KEY`

## ขั้นที่ 2: Deploy ดัชนีฐานข้อมูล (Indexes)

1. กลับไปที่ Terminal ใน VS Code
2. วางคำสั่งนี้แล้วกด Enter
   ```bash
   npx firebase deploy --only firestore:indexes
   ```
3. รอจนขึ้นข้อความ **`Deploy complete!`**
   - ถ้าระบบถามว่า *"Would you like to delete these indexes?"* ให้พิมพ์ `N` แล้วกด Enter
     (ชุดนี้ไม่ควรมีคำถามนี้ ถ้ามีให้ตอบ N ไว้ก่อนเพื่อความปลอดภัย)
   - ถ้าขึ้นว่าต้องล็อกอิน ให้พิมพ์ `npx firebase login` แล้วล็อกอินด้วย `psgsolution@gmail.com` จากนั้นทำข้อ 2 ใหม่
4. รอให้ดัชนีสร้างเสร็จ
   1. เข้า <https://console.firebase.google.com> แล้วเลือกโปรเจกต์ **nexuserp-base**
   2. เมนูซ้ายเลือก **Firestore Database** แล้วกดแท็บ **Indexes**
   3. ทุกบรรทัดต้องขึ้นสถานะ **Enabled** ถ้ายังเป็น **Building** ให้รอ 2–5 นาทีแล้วกดรีเฟรช

## ขั้นที่ 3: ส่งโค้ดขึ้น GitHub

Vercel ผูกกับ GitHub ไว้แล้ว เมื่อโค้ดเข้า branch `main` บน GitHub แล้ว Vercel จะสร้างเว็บเวอร์ชันใหม่ให้เอง

1. ใน Terminal ของ VS Code ให้พิมพ์คำสั่งทีละบรรทัด กด Enter หลังแต่ละบรรทัด และรอให้บรรทัดก่อนหน้าทำงานเสร็จก่อน
   ```bash
   git push origin feature/sales-real-data
   git switch main
   git pull origin main
   git merge feature/sales-real-data
   git push origin main
   ```
   **สิ่งที่ควรเห็นในแต่ละบรรทัด**
   - บรรทัด `git switch main` ควรขึ้นว่า `Switched to branch 'main'`
     ถ้าขึ้นว่า *"Your local changes would be overwritten"* ให้หยุดแล้วแจ้งผู้ดูแลระบบ
   - บรรทัด `git merge` ควรขึ้นคำว่า `Fast-forward`
     ถ้าขึ้นคำว่า `CONFLICT` ให้พิมพ์ `git merge --abort` แล้วหยุดและแจ้งผู้ดูแลระบบ
   - ถ้า `git push` ขอให้ล็อกอิน GitHub ให้ล็อกอินด้วยบัญชีที่มีสิทธิ์ในโปรเจกต์
2. กลับไปที่ Vercel แล้วเปิดแท็บ **Deployments**
   - จะเห็นรายการใหม่ขึ้นสถานะ **Building**
   - รอประมาณ 2–5 นาทีจนเปลี่ยนเป็น **Ready** (จุดสีเขียว)
   - ถ้าขึ้น **Error** (สีแดง) ให้คลิกเข้าไปดู คัดลอกข้อความ error ส่งให้ผู้ดูแลระบบ
     **ระหว่างนี้เว็บเดิมยังใช้งานได้ตามปกติ** และห้ามทำขั้นที่ 5
3. เมื่อเสร็จแล้ว พิมพ์คำสั่งนี้เพื่อกลับไปทำงานที่ branch เดิม
   ```bash
   git switch feature/sales-real-data
   ```

## ขั้นที่ 4: ทดสอบเว็บจริง (รอบที่ 1)

ข้อควรระวัง:
- เว็บจริงใช้ฐานข้อมูลจริง เอกสารที่สร้างตอนทดสอบให้ใส่คำว่า **ทดสอบ** ในหมายเหตุหรือรายละเอียดทุกครั้ง แล้วลบหรือยกเลิกเมื่อทดสอบเสร็จ
- ก่อนเริ่ม ให้กด `Ctrl + Shift + R` ที่หน้าเว็บ เพื่อให้เบราว์เซอร์โหลดเว็บเวอร์ชันใหม่

ล็อกอินด้วย `admin@admin.com` แล้วทำทีละข้อ ติ๊กเมื่อผ่าน:

**พื้นฐาน**
- [ ] หน้า Dashboard เปิดได้ ไม่เป็นหน้าขาว
- [ ] มุมบนแสดงชื่อบริษัทถูกต้อง

**ขาย**
- [ ] **ใบเสนอราคา:** สร้างใหม่ได้ และเลขเอกสารขึ้นถูกต้อง (ไม่มีคำว่า `TEMP`)
- [ ] **ใบสั่งขาย:** สร้างใหม่แบบ "ร่าง" ได้ เปิดดูแล้วกด **อนุมัติ** ได้ จากนั้นกด **ยกเลิก** ได้

**จัดซื้อ** (ต้องใช้ผู้ใช้ 2 คน เพราะห้ามอนุมัติเอกสารที่ตัวเองสร้าง)
- [ ] ด้วย `admin@admin.com`: สร้าง **ใบขอซื้อ** ได้ (เหตุผลใส่ "ทดสอบ")
- [ ] ด้วย `admin@admin.com`: กดอนุมัติใบขอซื้อที่ตัวเองสร้าง ระบบต้อง**ไม่ยอม** และขึ้นข้อความเตือน (ถือว่าผ่าน)
- [ ] ออกจากระบบ แล้วล็อกอินด้วย `sadmin@admin.com` จากนั้นเปิดใบขอซื้อเดิมแล้วกด **ไม่อนุมัติ** ได้
  (ใช้ "ไม่อนุมัติ" เพื่อไม่ให้ใบทดสอบค้างเป็นใบที่อนุมัติแล้ว)

**การเงิน**
- [ ] เปิดหน้ายื่นภาษี ภ.พ.30 แล้วตัวเลขขึ้น (เปิดดูอย่างเดียว ไม่ต้องกดยื่น)

ถ้ามีข้อไหนไม่ผ่าน ให้จดไว้ว่าเป็นหน้าไหนและขึ้นข้อความอะไร **แล้วหยุด ยังไม่ต้องไปขั้นที่ 5**

## ขั้นที่ 5: สำรองกฎเดิม แล้ว Deploy กฎความปลอดภัย (Rules)

กฎที่ใช้อยู่ตอนนี้ให้ทุกคนที่ล็อกอินเห็นและแก้ข้อมูลของ**ทุกบริษัท**ได้ กฎใหม่จะ:
- แยกข้อมูลแต่ละบริษัทออกจากกัน
- บังคับให้เอกสารสำคัญบันทึกผ่านระบบหลังบ้านเท่านั้น เช่น ใบกำกับภาษี สมุดรายวัน ใบสั่งซื้อ และใบสั่งขาย

**5.1 สำรองกฎเดิมไว้ก่อน (สำคัญมาก ห้ามข้าม)**
1. เข้า <https://console.firebase.google.com> แล้วเลือกโปรเจกต์ **nexuserp-base**
2. เมนูซ้ายเลือก **Firestore Database** แล้วกดแท็บ **Rules**
3. คลิกในกล่องข้อความ กด `Ctrl + A` แล้ว `Ctrl + C`
4. เปิด Notepad วางข้อความ แล้วบันทึกไว้ที่หน้า Desktop ชื่อ `rules-backup.txt`

**5.2 Deploy กฎใหม่**
1. กลับไปที่ Terminal ใน VS Code
2. วางคำสั่งนี้แล้วกด Enter
   ```bash
   npx firebase deploy --only firestore:rules
   ```
3. รอจนขึ้นข้อความ **`Deploy complete!`** (ประมาณ 30 วินาที)
4. **แจ้งผู้ใช้ทุกคน**ให้รีเฟรชหน้าเว็บ (`Ctrl + Shift + R`) หรือปิดแล้วเปิดเบราว์เซอร์ใหม่
   เพราะหน้าเว็บเวอร์ชันเก่าที่ค้างเปิดไว้จะบันทึกบางเอกสารไม่ได้

## ขั้นที่ 6: ทดสอบเว็บจริง (รอบที่ 2)

1. ปิดเบราว์เซอร์ทั้งหมด แล้วเปิดเว็บใหม่
2. ทำ checklist ในขั้นที่ 4 ซ้ำทั้งหมด
3. ล็อกอินด้วย `sadmin@admin.com` แล้วเช็กว่าหน้า Dashboard และหน้าตั้งค่าเปิดได้
4. เมนู **แดชบอร์ดผู้บริหาร** เปิดได้และตัวเลขขึ้น

ถ้าผ่านทั้งหมดถือว่าเสร็จ 🎉

## ถ้ามีปัญหา: วิธีย้อนกลับ

**ย้อนกฎ (ใช้เวลา 1 นาที)** ให้ทำเมื่อปัญหาเกิด**หลัง**ขั้นที่ 5
1. Firebase Console → **Firestore Database** → แท็บ **Rules**
2. ลบข้อความในกล่องทั้งหมด แล้ววางข้อความจากไฟล์ `rules-backup.txt` ที่สำรองไว้ในข้อ 5.1
3. กด **Publish**

**ย้อนเว็บ (ใช้เวลา 1 นาที)**
1. Vercel → โปรเจกต์ → แท็บ **Deployments**
2. หา deployment ก่อนหน้าที่สถานะ **Ready**
3. กดปุ่ม **⋯** ด้านขวา แล้วเลือก **Promote to Production** (หรือ **Instant Rollback**)

> ถ้าต้องย้อนทั้งสองอย่าง ให้**ย้อนกฎก่อน** แล้วค่อยย้อนเว็บ
> ดัชนี (ขั้นที่ 2) ไม่ต้องย้อน เพราะไม่มีผลเสียต่อเว็บเวอร์ชันเก่า

## เพิ่มผู้ใช้ใหม่และกำหนดตำแหน่ง

ผู้ใช้ 1 คนมีได้หลายตำแหน่ง สิทธิ์จะรวมกันตามทุกตำแหน่ง **กำหนดตำแหน่งได้เฉพาะ `sadmin@admin.com` (ผู้ดูแลสูงสุด)**

**เพิ่มพนักงานใหม่**
1. ล็อกอินด้วย `sadmin@admin.com` → เมนู **ตั้งค่า** → **จัดการผู้ใช้งานและสิทธิ์**
2. กดปุ่ม **คัดลอกลิงก์สมัครผู้ใช้** แล้วส่งลิงก์ให้พนักงาน พร้อมรหัสบริษัท (เช่น `COM-NEXUS-01`)
3. พนักงานเปิดลิงก์ กรอกข้อมูล แล้วกดสมัคร
4. กลับมาที่แท็บ **รออนุมัติ** → กด **อนุมัติ** → ติ๊กตำแหน่งที่ต้องการ (เลือกได้หลายตำแหน่ง) → กด **อนุมัติ**
5. พนักงานล็อกอินได้ทันที และจะเห็นเฉพาะเมนูของตำแหน่งตัวเอง

**เปลี่ยนตำแหน่งของผู้ใช้เดิม**
1. แท็บ **ผู้ใช้งาน** → แถวของผู้ใช้ → กด **กำหนดตำแหน่ง**
2. ติ๊กหรือเอาเครื่องหมายถูกออก แล้วกด **บันทึกตำแหน่ง**
3. ผู้ใช้กด `Ctrl + Shift + R` (รีเฟรช) เพื่อรับสิทธิ์ใหม่

| ตำแหน่ง | เห็น / ทำได้ |
|---|---|
| ผู้บริหาร | ดูทุกโมดูล แดชบอร์ดผู้บริหาร (เงินสด ลูกหนี้ เจ้าหนี้ กำไร) อนุมัติซื้อทุกวงเงิน อนุมัติใบเสนอราคาและโครงการ |
